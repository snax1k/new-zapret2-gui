ИСПРАВЛЕНИЕ ЗАПУСКА (регрессия v0.0.5)
--------------------------------------

Симптом:
  failed to register ipset '../host-list/ipset-telegram.txt'
  cannot access ipset file '../host-list/ipset-telegram.txt'
  winws.exe завершился с кодом 1

Причина: относительный путь с переходом на уровень выше. В v0.0.5 списки
переехали из bin\ в host-list\, и команда стала ссылаться на них как
../host-list/<файл>. Ядро на разборе --ipset проверяет файл через stat() и
завершает работу, если проверка не прошла.

При этом файл существовал и путь был корректным:
  - файл лежал в %LOCALAPPDATA%\Zapret2-GUI\host-list\ (364 байта);
  - рабочий каталог ядра — соседний bin\, то есть ../host-list/ указывает
    ровно туда;
  - mdig.exe из той же сборки zapret (тоже cygwin) такой относительный путь
    резолвит без проблем.

Почему именно winws на нём спотыкается, установить не удалось: воспроизвести
запуск ядра для отладки не получается, оно требует прав администратора.
Поэтому вместо поиска причины устранён сам класс проблемы — приложение
подставляет в команду АБСОЛЮТНЫЙ путь к каталогу списков:

  --hostlist="C:/Users/<имя>/AppData/Local/Zapret2-GUI/host-list/list-general.txt"

Так же поступают рабочие конфигурации zapret для Windows (в general.bat из
Flowseal/zapret-discord-youtube пути к спискам тоже абсолютные).

Как это устроено:
  - в пресете путь записывается через маркер {LISTS}/list-general.txt;
  - перед запуском ядра маркер заменяется на абсолютный путь, значение берётся
    в кавычки, разделители — прямые слеши (безопасно и для путей с пробелами
    в имени пользователя, и для разбора командной строки cygwin-сборкой);
  - маркер виден в интерфейсе на вкладке «Пресеты», в лог пишется уже
    подставленный путь.

Дополнительно: перед запуском проверяется наличие всех файлов списков.
Если какого-то нет, в логе появится «Файл списка не найден: <путь>» и запуск
отменяется — вместо невнятного падения ядра с кодом 1.

ЧТО НЕ ИЗМЕНИЛОСЬ
-----------------
Стратегия обхода, списки доменов, порты, профили — те же, что в v0.0.4/v0.0.5.
Раскладка каталогов и экспорт/импорт пресетов из v0.0.5 сохранены.
Пресеты, хостлисты и настройки НЕ сбрасываются при этом обновлении.
