ПРЕДУПРЕЖДЕНИЕ О СИСТЕМНОМ ПРОКСИ
---------------------------------

Единственное изменение этой версии. При запуске ядра приложение проверяет
настройки Windows и, если включён системный прокси, пишет в лог:

  [warn] [Proxy] В Windows включён системный прокси: 127.0.0.1:10808
  [warn] [Proxy] HTTP(S)-трафик приложений уходит на прокси, а не напрямую.
                 Такой трафик идёт через loopback, который фильтр WinDivert
                 исключает, поэтому обход его НЕ ВИДИТ и не обрабатывает.
  [info] [Proxy] Через прокси не идёт UDP: голос Discord и QUIC по-прежнему
                 обрабатываются обходом.

ЗАЧЕМ ЭТО НУЖНО
---------------

Фильтр WinDivert начинается с "!impostor and !loopback". При включённом
системном прокси приложения отправляют HTTP(S) не на адрес сайта, а на
127.0.0.1 — то есть в loopback. Такой трафик winws не видит физически.

Симптом выглядит пугающе: обход включён, ядро работает, все шесть профилей
загружены, а в логе ноль применённых десинхронизаций и ноль распознанных имён
хостов. Переключение стратегий при этом не меняет ничего, потому что ни один
профиль не срабатывает.

Разделение труда при включённом прокси:

  TCP 80/443 (браузер, вход в Discord, чат, апдейтер)  -> прокси
  UDP (голос Discord, QUIC)                            -> обход

ПРОВЕРКА
--------
  powershell -ExecutionPolicy Bypass -File scripts\check_discord.ps1

Скрипт печатает состояние обхода и системного прокси (включая то, слушает ли
кто-нибудь его порт) и проверяет каждый эндпоинт Discord двумя путями —
напрямую и через прокси. Права администратора не нужны.

Стратегия обхода, списки, профили, переключатель стратегий YouTube — всё как
в v0.0.8. Пресеты, хостлисты и настройки не сбрасываются.
