# Zapret2 Control Center

Графическая оболочка для [bol-van/zapret](https://github.com/bol-van/zapret) под Windows —
обход DPI для YouTube и Discord плюс встроенный мост для Telegram.
Собирается в один переносимый `.exe`,
который распаковывает ядро и списки при первом запуске.

| | |
|---|---|
| Текущая версия | **v0.4.2**, тестовая **v0.4.3-test** (новый дизайн) |
| Ядро в поставке | zapret **v72.13** (`winws.exe` + WinDivert 2.2 x64) |
| Требования | Windows 10/11 x64, .NET Framework 4.x, права администратора |

---

## Как устроено

> Перед правкой стратегии обхода или командной строки `winws` читайте
> **[MEMORY.md](MEMORY.md)** — там собраны правила ядра, нарушение которых
> роняет `winws` с кодом 1, разобранные баги с их настоящими причинами
> и смысл каждого параметра в пресете.

Приложение — это WinForms-хост с встроенным WebView2, внутри которого крутится
React-интерфейс. Всё лежит в одном exe: `dist.zip`, `bin.zip` и `lists.zip`
вшиты в него ресурсами и разворачиваются в `%LOCALAPPDATA%\Zapret2-GUI\`.

```
%LOCALAPPDATA%\Zapret2-GUI\
├─ bin\          ← ядро; перезаписывается целиком при каждом запуске
│   ├─ winws.exe, cygwin1.dll, WinDivert.dll, WinDivert64.sys
│   └─ *.bin     ← фейковые пейлоады TLS/QUIC/STUN
├─ host-list\    ← списки доменов и подсетей
│   ├─ list-general.txt, list-google.txt, list-exclude.txt
│   └─ list-user.txt, list-exclude-user.txt   ← пишет раздел «Списки сайтов»
├─ dist\         ← интерфейс
├─ logs\         ← zapret2.log + до 10 zip-архивов ротации (порог 10 МБ)
├─ settings.json ← все настройки: пресеты, переключатели, тема, прокси Telegram
└─ WebViewData\  ← служебный профиль WebView2
```

Каталоги разделены намеренно: `bin\` считается заменяемым и затирается
обновлением, а `host-list\` содержит в том числе пользовательские файлы,
которые терять нельзя.

### Интерфейс

С 0.4.3 оформление по макету редизайна (Gemini, `docs/design/`):

* **Только тёмные темы** — «Чёрная» (чистый чёрный, для OLED) и «Тёмная»
  (графит). Акцент — фиолетово-синий, синий, бирюзовый или красный. Своё
  изображение фоном ставится под затемняющий слой.
* **Токены** цветов и тем — [`src/lib/theme.ts`](src/lib/theme.ts) (CSS-переменные)
  и `tailwind.config.js` (`bg-app`, `bg-s1..s3`, `text-t1..t3`, `border-line`,
  `bg-ac`). Старые классы `indigo-*`/`slate-*` перекрашены через те же
  переменные. Шрифты системные: Segoe UI Variable / Segoe UI и Cascadia Mono.
* **Общие элементы** — [`src/components/ui.tsx`](src/components/ui.tsx):
  кнопки, карточки, переключатели, статусные точки, бейджи, вкладки.

Разделы меню (на узком окне, меньше 900 px, меню сворачивается до значков):

| Раздел | Что там |
|---|---|
| Главная | кнопка питания и состояние словами; при работающем обходе — обработано соединений, распознано сайтов, PID ядра; «Что сейчас настроено» с отметкой, проверен ли способ подбором; «Проверка компьютера»; быстрые переключатели |
| Подбор | экран автоподбора: «Весь пресет», «Discord и сайты», «YouTube»; оттуда же — «Стратегии (для опытных)»: ручной выбор способов, пресеты, состав команды и строка запуска |
| Telegram | встроенный мост, ссылка, статистика, настройки |
| Списки сайтов | свои домены и исключения поверх встроенных списков |
| Диагностика | цепочка DNS → TCP → TLS по целям |
| Журнал | события программы и ядра с фильтрами |
| Настройки | тема и акцент, поведение крестика, запуск вместе с Windows и автовключение обхода, обновления, кэш Discord, мастер, обслуживание |

Внизу меню всегда видно, работает ли обход и сколько.

### Стратегия обхода

Единственный пресет собирает командную строку `winws.exe` из пяти профилей,
разделённых `--new`. Порядок важен: ядро выбирает **первый** подходящий профиль
(`dp_find` в `nfq/desync.c`), а профиль со списком доменов не может выиграть,
пока имя хоста неизвестно.

| # | Профиль | Отбор |
|---|---------|-------|
| 1 | QUIC / HTTP-3 | UDP 443, домены из списков |
| 2 | Голос Discord | UDP 19294-19344, 50000-50100, `--filter-l7=discord,stun` |
| 3 | Медиасерверы Discord | TCP 2053,2083,2087,2096,8443, `discord.media` — стратегия группы Discord |
| 4 | YouTube и Google | TCP 443, `list-google.txt` |
| 5 | Остальные сайты | TCP 80,443, `list-general.txt` |

Профиля Telegram здесь нет с 0.1.5 и быть не может. Telegram закрывают не по
содержимому, а по маршруту: SYN до подсетей дата-центров уходит, SYN-ACK не
приходит ни разу. Десинхронизация работает с содержимым первых пакетов, а тут
соединение не устанавливается вовсе — резать нечего. Telegram решается
отдельным мостом, см. ниже.

Стратегии переключаются из интерфейса двумя группами: «YouTube и Google»
(профиль 4) и «Сайты и Discord» (профили 5 и 3 — медиасерверы Discord с 0.4.2
идут вместе с discord.com). Библиотека — 32 варианта десинхронизации и эталон
«Выключено»; у каждой группы свой порядок перебора (`STRATEGY_ORDER`), самые
частые победители впереди. С 0.4.2 в ней варианты по образцу
[Flowseal](https://github.com/flowseal/zapret-discord-youtube): фейки с именами
российских сайтов (vk.com, gosuslugi.ru, ya.ru, mail.ru, ozon.ru — против
заморозки соединений к иностранным дата-центрам, которую ТСПУ снимает по
белому списку имён) и `fooling=ts` (нужны метки времени TCP в Windows —
предполётная проверка показывает их и включает по кнопке).

Голос Discord захватывается на 50000-50100, а не на 50000-65535: широкий
диапазон тянул через ядро весь UDP игр и Steam. Пейлоад голосового фейка —
стандартный ядра: у Flowseal там QUIC-пакет на 1200 байт, а такой у нас уже
ломал подключение к части комнат (см. MEMORY.md).

Вся сборка команды живёт в одном месте — [`src/lib/zapretCommand.ts`](src/lib/zapretCommand.ts).
Там же зафиксированы правила ядра, нарушение которых роняет `winws` с кодом 1:
без `--wf-tcp`/`--wf-udp` он не стартует вообще, а `--dpi-desync-autottl`
принимает только формат `[+|-]<delta>[:<min>[-<max>]]`.

### Автоподбор

Экран «Подбор» ([`src/views/AutotuneView.tsx`](src/views/AutotuneView.tsx)).
Перебирает варианты профиля YouTube или профиля сайтов и Discord, запуская
ядро с каждым и открывая настоящие соединения к целям. Первым идёт эталон
«без обхода»: если цели открываются и так, перебор прекращается.

**«Весь пресет»** — рекомендуемый путь: подбор Discord и сайтов, затем
YouTube, затем **проверка собранной команды целиком** на всех целях сразу —
по отдельности способы могут работать, а вместе мешать друг другу (ядро
берёт первый подходящий профиль). Само ничего не применяется: в конце
сводка, «Применить пресет» и «Вернуть как было».

Если цель не открылась ни при одном варианте, подбор берёт её следующий
отвечающий адрес из DNS и повторяет перебор один раз: бывает, что режется
сам адрес, а не соединение.

**Проба — приветствие настоящего Chromium, а не .NET**
([`src-native/ChromeHello.cs`](src-native/ChromeHello.cs)). Образец записан с
Edge 153: 1729 байт, постквантовый X25519MLKEM768, GREASE, ECH, ALPN — не
помещается в один TCP-сегмент, как и у клиента Discord. Перед каждой пробой
меняются имя сайта, случайное число и номер сессии. Успех — ServerHello,
повторивший наш номер сессии: его может прислать только сервер, получивший
приветствие. Полное рукопожатие не нужно.

Почему так, а не `SslStream`. Exe собран `csc` без атрибута `TargetFramework`,
и .NET в нём по умолчанию шлёт **TLS 1.0** на 115 байт. Discord такое
отвергает — до 0.3.3 подбор не мог найти стратегию для Discord ни разу.
Поведение .NET нашего exe проверяется только кодом, собранным тем же `csc`:
в PowerShell значения по умолчанию другие.

Цель, не открывшаяся ни разу, обрывает проверку варианта: все цели нужны
одновременно. Цели Discord: discord.com, gateway.discord.gg, cdn.discordapp.com,
updates.discord.com и `latency.discord.media:2053` — медиасерверы на
альтернативном порту Cloudflare.

**Три шага.** Быстрый отсев — одна попытка на цель, неподходящий вариант
отваливается за несколько секунд. Первые четыре прошедших — полная проверка,
по три попытки. Затем **проверка в браузере**: Microsoft Edge без окна
(`--headless --no-proxy-server --disable-quic`, чистый профиль на каждый
запуск) открывает страницу входа Discord или главную YouTube и обязан
дождаться полной загрузки за 12 с. Это тот же Chromium, что внутри Discord,
с тем же TLS 1.3 и всеми подресурсами — так ловится то, чего проба не видит:
вариант пропускает рукопожатие, а данные замерзают после 16–20 КБ. Эталон
«без обхода» тоже проходит браузер, прежде чем подбор скажет «обход не
нужен». Нет Edge — шаг пропускается с предупреждением.

Выбор стратегии помечает варианты по итогам последнего подбора: зелёная
точка — прошёл, красная — нет; про непроверенный выбранный вариант пишет
отдельно. Ради этого и сделано: 2026-10-12 у Discord стоял вручную выбранный
вариант, который подбор не проверял, — и клиент открывался через раз.

### Проверка компьютера

Карточка на главной ([`src/components/PreflightPanel.tsx`](src/components/PreflightPanel.tsx))
отвечает на вопрос «почему обход может ничего не сделать» до того, как
человек начнёт перебирать стратегии:

* **системный прокси** — HTTP(S) приложений уходит в loopback, ядро его не видит;
* **Discord ходит через прокси** — соединения Discord на адрес системного
  прокси (VPN-клиенты вроде Happ): загрузка и сообщения идут мимо обхода,
  и никакая стратегия не поможет;
* **трафик уходит через туннель** VPN;
* **метки времени TCP** — без них не работают способы с `ts`; кнопка
  «Включить» выполняет `netsh interface tcp set global timestamps=enabled`;
* **посторонние winws.exe и другие обходчики** — дерутся за драйвер.

### Отчёт и журнал

Каждый прогон пишет отчёт `logs/autotune-*.txt` (последние пять, ротация
журнала их не трогает): по каждой пробе — результат, видело ли её ядро,
сколько раз обработало, какое имя прочитало, были ли сбросы RST и с каким
TTL, плюс итог браузера. Переснять образец приветствия:
`scripts/diag/capture-chrome-hello.ps1`.

Журнал ядра с 0.4.2 не пишет пакетный шум (заголовки каждого пакета, UDP,
«cached profile», «reinject»): во время звонка Discord он давал 10 МБ за
10 минут, и запуск клиента затирался раньше, чем его успевали разобрать.

Тестовые сборки (`-test` в версии) понимают ключ `--devtools-port=N` —
порт удалённой отладки WebView2, чтобы проверять подбор на живой программе
из скрипта. В выпусках ключ игнорируется.

### Автозапуск и перезапуск ядра

С 0.5.0 программа доводит до «запустил один раз и забыл».

**Запуск вместе с Windows** — «Настройки → Поведение» или последний шаг
мастера. Это задача Планировщика заданий `Zapret2 Control Center (<имя
пользователя>)`: при входе, с наивысшими правами — поэтому без запроса UAC
(программы из ключа `Run` в реестре Windows с повышением прав не
запускает). Создаётся через COM-интерфейс Планировщика, а не `schtasks.exe`:
тот отдаёт вывод в OEM-кодировке, и путь с кириллицей не прочитать. В
настройках задачи: без ограничения по времени (по умолчанию Планировщик
снимает задачу через 72 часа), запуск от батареи, обычный приоритет (по
умолчанию «ниже среднего» — его унаследовал бы winws). Состояние в
интерфейсе — то, что в Планировщике, а не флажок в настройках.

Задача запускает exe с ключом `--autostart`: окно не показывается
(`SetVisibleCore` подавляет первый показ), программа сразу в трее, но
интерфейс загружается — включать обход умеет только он. Если файл, на
который указывает задача, пропал, программа при старте переводит задачу на
себя; если он на месте (открыта другая копия), настройки предлагают
«Запускать этот».

**Сразу включать обход** — при каждом запуске программы, один раз за
запуск (перезагрузка страницы не включает обход повторно), не раньше
пройденного мастера. Ждёт маршрут от нативной части (1–2 с), чтобы ядро
сразу привязалось к сетевой карте; без маршрута — через 5 с. Включение
автозапуска включает и это.

**Перезапуск упавшего ядра.** Если winws умирает посреди работы, программа
поднимает его с теми же аргументами через 3, 10, 30, 60 и 120 с; пока
ждёт — состояние «перезапуск», кнопка выключает обход и отменяет попытку.
Серия сбрасывается, если ядро проработало 5 минут. Не перезапускает: во
время автоподбора; если ядро умерло в первые 1,5 с после запуска
пользователем (это ошибка настройки); если в системе работает чужой
winws.exe или другой обходчик — запуск снял бы его, и началась бы война за
драйвер. Если окно спрятано в трей, об отказе сообщает всплывающее
уведомление; подсказка значка в трее всегда показывает состояние обхода.

Выключение компьютера и выход из системы закрывают программу, а не
прячут в трей: иначе Windows показывала бы «приложение мешает завершить
работу».

Проверка в браузере: `?mock=crash` (ядро падает через 4 с и поднимается),
`?mock=moved` (автозапуск указывает на другой файл).

## Мастер первого запуска

[`src/components/SetupWizard.tsx`](src/components/SetupWizard.tsx). Открывается
сам, пока в настройках нет ключа `zapret2_wizard_v1` (`done|<версия>` или
`skipped|<версия>`); потом — из «Настройки → Мастер настройки».

Шаги: знакомство → проверка компьютера → Discord → YouTube → Telegram → итог.
Своих проверок у мастера нет — он вызывает то же, что и остальная программа:
`runPreflight`, `startAutotune`, `startTgProxy`. Вывод по итогам подбора общий
с экраном «Подбор» — [`src/lib/autotune.ts`](src/lib/autotune.ts), чтобы они
не противоречили друг другу.

Полностью надёжный способ применяется сам; способ «через раз» — только с
согласия человека; при «не помогло ничего» настройки не трогаются. Мастер
перекрывает окно под заголовком, а не поверх него: он открыт минутами, и
программу должно быть можно свернуть.

Приветствие говорит по-разному с тремя людьми: впервые запустившим,
обновившимся с прежней версии (есть настройки, нет ключа мастера) и
открывшим мастер вручную.

### Проверка интерфейса без программы

`npm run dev`, затем `http://localhost:1420/?mock` — интерфейс получает
имитацию нативной части ([`src/dev/mockHost.ts`](src/dev/mockHost.ts)):
проверку окружения, ход подбора (отсев, финалисты, проверку в браузере,
заморозку), мост. Сценарии: `?mock`, `?mock=clean`, `?mock=partial`,
`?mock=none`, `?mock=free`, `?mock=rival`, `?mock=address` (первый адрес цели
молчит, подбор меняет адрес), `?mock=crash` (ядро падает и перезапускается),
`?mock=moved` (автозапуск указывает на другой файл) — описаны в шапке файла. Мастер снова откроется
после `localStorage.clear()`.

После правки `src/context/AppContext.tsx` горячая перезагрузка Vite роняет
страницу с «useApp must be used within an AppProvider» — подменяется модуль
контекста. Это не ошибка: обновите страницу.

В сборку имитация не попадает: подключение стоит за `import.meta.env.DEV`, и
Vite вырезает ветку вместе с модулем. Проверено по `dist/assets` — один файл
скриптов, строк имитации в нём нет.

## Прокси Telegram

Отдельный раздел интерфейса и отдельный механизм: `src-native/TgProxy.cs`,
к `winws` отношения не имеет. Обход может быть выключен, а мост — работать.

Мост поднимает слушатель MTProxy на `127.0.0.1:1443`, разбирает
обфусцированное рукопожатие клиента, достаёт из него номер дата-центра и
выводит соединение наружу **по WebSocket поверх TLS** — тем транспортом,
которым пользуется веб-версия Telegram. Снаружи это обычный HTTPS к сайту.

Ссылка `tg://proxy?server=…&secret=dd…` отдаётся системе, её подхватывает
установленный клиент: штатный обработчик схемы `tg:`, никаких ухищрений.

### Три пути до дата-центра, в этом порядке

| | куда | когда работает |
|---|---|---|
| 1 | `wss://kws<N>.web.telegram.org` по адресу дата-центра | адреса Telegram открыты |
| 2 | `kws<N>.<узел за Cloudflare>` | адреса закрыты подсетями — **основной рабочий путь в РФ** |
| 3 | прямой MTProto на 443 | Telegram не блокируют вовсе |

Первый путь на заблокированной сети не проходит: `kws*.web.telegram.org`
живёт на тех же адресах Telegram и попадает под блокировку вместе с ними.
Проверено: на сети тестовой машины `149.154.167.51`, `149.154.167.99`,
`149.154.175.50`, `149.154.171.5` и `91.105.192.100` не отвечают на 443
вовсе, при том что Cloudflare и `1.1.1.1` отвечают за 20-40 мс.

Поэтому отказ по TCP откладывает адрес на час, а остальные дата-центры —
на пять минут: блокируют подсетями, и без этого каждый новый центр стоил бы
клиенту ещё одного семисекундного таймаута. Короткая пауза на соседях нужна,
чтобы разовый сбой одного узла не загнал мост в обход на целый час.

Список запасных узлов лежит в исходнике **сдвинутым**, а не открытым текстом,
и это не ребячество: открытый список вытаскивается из сборки поиском по
строкам, после чего домены закрывают пачкой. Сдвиг тот же, что в
`Flowseal/tg-ws-proxy`, иначе списки разъехались бы. Обновляется при запуске
моста, best-effort (до 0.3.3 не обновлялся ни разу — `WebClient` шёл к
GitHub по TLS 1.0).

Узлы нередко отвечают `503` — за 100-300 мс, и тот же узел через пару секунд
снова работает. Поэтому перебор ограничен не числом узлов, а временем: до
8 с на соединение, до 3,5 с на узел. Если узлы не ответили, а адрес
дата-центра уже признан закрытым, мост сразу сбрасывает соединение, не ходя
напрямую: Telegram переподключится и попадёт на другой узел. Замер на 40
соединениях: 40 из 40, первое 7,3-7,7 с, остальные 0,2-4,6 с.

### Что не портировано

FakeTLS (`ee`-секреты с маскировкой под сайт), свой воркер Cloudflare,
PROXY-протокол, тестовые дата-центры, пул прогретых соединений. Для работы
Telegram они не нужны.

### Проверка без Telegram

Мост проверяется программой `scripts/diag/TgProxyTest.cs` (сборка — в шапке
файла), которая сама изображает клиента: собирает
обфусцированный init-пакет, шлёт `req_pq_multi` и ждёт `resPQ`
(конструктор `0x05162463`). Пришёл resPQ — значит прошла вся цепочка:
разбор рукопожатия, четыре потока AES-CTR, нарезка на кадры, WebSocket и
сам дата-центр. На всех пяти дата-центрах проверено.

**AES-CTR в .NET Framework нет.** Есть CBC, ECB и CFB. CTR собран из ECB
вручную: шифруется счётчик, результат складывается с данными по XOR,
инкремент — все 16 байт как одно число справа налево. Расходиться с эталоном
тут нельзя ни на бит.

**`ClientWebSocket` не подошёл.** Соединение открывается по IP-адресу, а имя
в SNI и в заголовке `Host` задаётся отдельно — иначе не сделать ни обращение
по фиксированному адресу дата-центра, ни подмену имени в TLS. Рукопожатие
HTTP и кадры написаны руками.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

Скрипт ставит зависимости, собирает фронтенд через Vite, пакует ресурсы и
компилирует exe через `csc.exe` из .NET Framework 4. Результат —
`release-v<версия>\Zapret2-GUI-v<версия>-portable.exe`.

`scripts\build.ps1` сохранён в UTF-8 **с BOM**: без него PowerShell 5.1 ломает
кириллицу в выводе.

### Проверка командной строки

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify_args.ps1
```

Прогоняет все способы библиотеки через `winws --wf-save` — ядро разбирает
аргументы, собирает фильтр WinDivert и выходит, не загружая драйвер. Так
проверяются пути к спискам, наличие `.bin`-пейлоадов и синтаксис всех опций.
Список способов берётся прямо из `src/lib/zapretCommand.ts`
(`scripts/dump_strategies.mjs`), поэтому проверяется ровно то, что попадёт в
exe. Нужны права администратора и node.

### Значок

Значок «Z2» нарисован в SVG: [`assets/icon/`](assets/icon/). `icon.svg` —
основной рисунок (кадры от 32 px), `icon-16.svg`, `icon-20.svg`,
`icon-24.svg` — упрощённые варианты под пиксельную сетку: трей и заголовок
окна при масштабе 100–150 %. Уменьшенный с 256 рисунок в этих размерах
расплывается в пятно.

```powershell
npm i --no-save @resvg/resvg-js@2.6.2
node scripts/make_icon.mjs
```

Скрипт собирает `app.ico` (9 кадров, 16–256 px) и кладёт `public/logo.svg`
(иконка вкладки в режиме разработки). Генератор не входит в зависимости
проекта: значок меняется редко, а сборке нужен только готовый `app.ico`.

Нативная часть берёт значок через `SHDefExtractIcon` нужного размера
(`LoadAppIcon` в `NativeApp.cs`), а не `Icon.ExtractAssociatedIcon` — тот
отдаёт только 32 px, и Windows ужимает его в трей. `new Icon("app.ico")` не
годится: .NET Framework не понимает PNG-кадры. В интерфейсе тот же рисунок —
[`src/components/AppLogo.tsx`](src/components/AppLogo.tsx), двойка там
окрашена в цвет акцента.

## Распространение и обновления

Репозиторий публичный, сборки публикуются в
[Releases](https://github.com/snax1k/new-zapret2-gui/releases).

### Как обновляется приложение

Проверка выполняется при запуске (через 8 секунд, не чаще раза в шесть часов)
и по кнопке в настройках. Автопроверку можно выключить там же. Найденное
обновление окно не открывает — о нём сообщает плашка в боковом меню.

`checkForUpdates` сравнивает `APP_VERSION` с `tag_name` последнего релиза.
Если вышла новее — предлагает поставить:

1. скачивает `Zapret2-GUI-v<версия>-portable.exe` из ассетов релиза;
2. сверяет SHA-256 с `SHA256SUMS.txt` из того же релиза;
3. запускает вспомогательный `.cmd`, который ждёт выхода процесса по PID,
   подменяет exe и стартует новую версию.

Третий шаг нужен потому, что запущенный exe нельзя перезаписать самому себе.

**Установка выполняется только при наличии `SHA256SUMS.txt`.** Нет
контрольной суммы — кнопка не показывается: иначе приложение запускало бы
непроверенный файл с правами администратора. Ссылка на загрузку проверяется
на принадлежность github.com.

Ядро zapret этим механизмом не обновляется: `winws.exe` и WinDivert вшиты в
exe ресурсами и приезжают только с новой сборкой.

### Версия живёт в четырёх местах

`scripts/build.ps1`, `AppVersion` в `src-native/NativeApp.cs`, `APP_VERSION`
в `src/context/AppContext.tsx` и `version` в `package.json`. Разойдутся —
проверка обновлений начнёт врать. Сборка падает с понятным сообщением, если
значения не совпали.

В разметке версию писать нельзя: заголовок окна и стартовая запись в логе
берут её из `APP_VERSION`. Сборка отдельно проверяет, что строк вида
`v0.0.0-portable` в `src/components` и `src/views` не осталось.

### Публикация релиза

Один раз сохранить токен (скрытый ввод, шифрование DPAPI — расшифровать
может только эта учётная запись на этой машине):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\save_release_token.ps1
```

Дальше для каждого выпуска:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\publish_release.ps1
```

Создаёт тег и релиз, заливает exe и `SHA256SUMS.txt`, описание берёт из
`release-v<версия>/README.txt`. Токен лежит в
`%LOCALAPPDATA%\Zapret2-Release\release-token.xml` — отдельно от данных
приложения, чтобы его не снесла очистка `Zapret2-GUI`. Переменная
`GITHUB_TOKEN`, если задана, имеет приоритет.

## Антивирусы и ложные срабатывания

Сборки этого проекта время от времени попадают под эвристику антивирусов.
Windows Defender определял `v0.1.4` как `Trojan:Win32/Wacatac.B!ml`,
Яндекс.Браузер отказывался её скачивать. Суффикс `!ml` — вердикт машинного
обучения, а не совпадение с сигнатурой.

Приложение собирает на себе все признаки, на которые такая эвристика
реагирует:

* **не подписано** — издатель для системы неизвестен;
* **нулевая репутация** — файл новый и скачан считанные разы;
* **поведение действительно похоже на нежелательное** — распаковывает из
  ресурсов драйвер сетевой фильтрации WinDivert, ставит его и вмешивается в
  чужие TCP-соединения. Инструменты класса zapret многие движки штатно
  относят к HackTool.

Третий пункт не устраняется: это и есть назначение программы.

### Что помогает, а что нет

| | результат |
|---|---|
| Подпись кода сертификатом | решает задачу; репутация накапливается на издателя, а не на каждый файл |
| Отправка ложного срабатывания вендору | снимает конкретный вердикт за 1–3 дня, но без сертификата — на каждую сборку |
| Пересборка | **не помогает.** Вердикт возвращается, когда облачная модель оценивает новый файл: у `v0.1.4` это заняло около двух часов |
| Упаковка в архив | **не помогает.** Defender проверяет содержимое архивов — `.7z` со сборкой внутри был опознан так же |
| Переименование, сжатие упаковщиком | делает хуже: сами по себе признаки вредоноса |

Проверять надо **скачанный** файл, а не собранный локально: срабатывание
происходит по метке «загружено из интернета». Если после скачивания файл не
читается — его забрал антивирус.

### Как убедиться, что сборка не подменена

В каждом релизе рядом с exe лежит `SHA256SUMS.txt`.

```powershell
Get-FileHash .\Zapret2-GUI-v<версия>-portable.exe -Algorithm SHA256
```

Совпало со строкой в `SHA256SUMS.txt` — файл ровно тот, что собран из
исходников. Не совпало — запускать нельзя.

Обновление внутри приложения сверяет сумму само и **не устанавливается**,
если она не сошлась или если `SHA256SUMS.txt` в релизе нет: иначе
приложение запускало бы непроверенный файл с правами администратора.

## Другие платформы

Разобрано 2026-10-14, отложено.

**Linux (Ubuntu, Fedora, Arch) — реально.** zapret родом оттуда: `nfqws` —
оригинал, `winws` — его порт, библиотека способов переносится почти как
есть, React-интерфейс — почти целиком. Работа — в обвязке: новая нативная
часть вместо WinForms/WebView2/.NET Framework (кандидаты — .NET 8 с
Photino/Avalonia, чтобы сохранить C#-код подбора и моста; Tauri; Electron —
он ещё и даёт свой Chromium для проверки в браузере); разделение на
интерфейс от пользователя и службу-помощник с правами root (графику от root
Wayland не пускает), причём помощник должен принимать не строку аргументов,
а id пресета и способа; правила nftables/iptables с NFQUEUE под ufw,
firewalld и что угодно у Arch — и их гарантированное снятие, иначе
пропадает сеть; пакеты `.deb`/`.rpm`/AUR вместо одного exe (Flatpak не
годится), SELinux на Fedora, трей в GNOME.

**macOS — почти бесполезно.** Divert-сокетов нет (`docs/bsd.md` ядра):
работает только `tpws` — прозрачный TCP-прокси через `pf`, на
недокументированном `DIOCNATLOOK`. Без фейков, без UDP: голос Discord и
QUIC не обходятся, из 32 способов применимы единицы. Плюс подпись и
нотаризация для помощника. Переносим разве что мост Telegram.

Первый шаг, если вернёмся: в нынешнем проекте вынести связь интерфейса с
нативной частью в отдельный слой и разрезать `NativeApp.cs` на переносимое
(подбор, проба, мост, журнал) и Windows-специфику; затем прототип Linux без
интерфейса — служба, `nfqws`, nftables — на живом провайдере.
