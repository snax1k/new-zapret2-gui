# Zapret2 Control Center

Графическая оболочка для [bol-van/zapret](https://github.com/bol-van/zapret) под Windows —
обход DPI для YouTube, Discord и Telegram. Собирается в один переносимый `.exe`,
который распаковывает ядро и списки при первом запуске.

| | |
|---|---|
| Текущая версия | **v0.1.4** |
| Ядро в поставке | zapret **v72.13** (`winws.exe` + WinDivert 2.2 x64) |
| Требования | Windows 10/11 x64, .NET Framework 4.x, права администратора |

---

## Как устроено

> Перед правкой стратегии обхода или командной строки `winws` читайте
> **[MEMORY.md](MEMORY.md)** — там собраны правила ядра, нарушение которых
> роняет `winws` с кодом 1, разобранные баги с их настоящими причинами
> и смысл каждого параметра в пресете.

Приложение — это WinForms-хост с встроенным WebView2, внутри которого крутится
React-интерфейс. Всё лежит в одном exe: `dist.zip`, `bin.zip` и `lists.zip`
вшиты в него ресурсами и разворачиваются в `%LOCALAPPDATA%\Zapret2-GUI\`.

```
%LOCALAPPDATA%\Zapret2-GUI\
├─ bin\          ← ядро; перезаписывается целиком при каждом запуске
│   ├─ winws.exe, cygwin1.dll, WinDivert.dll, WinDivert64.sys
│   └─ *.bin     ← фейковые пейлоады TLS/QUIC/STUN
├─ host-list\    ← списки доменов и подсетей
│   ├─ list-general.txt, list-google.txt, list-exclude.txt
│   ├─ ipset-telegram.txt
│   └─ list-user.txt, list-exclude-user.txt   ← пишет вкладка «Хостлисты»
├─ dist\         ← интерфейс
├─ logs\         ← zapret2.log + до 5 zip-архивов ротации (порог 10 МБ)
└─ WebViewData\  ← localStorage: пресеты, переключатели, тема
```

Каталоги разделены намеренно: `bin\` считается заменяемым и затирается
обновлением, а `host-list\` содержит в том числе пользовательские файлы,
которые терять нельзя.

### Стратегия обхода

Единственный пресет собирает командную строку `winws.exe` из шести профилей,
разделённых `--new`. Порядок важен: ядро выбирает **первый** подходящий профиль
(`dp_find` в `nfq/desync.c`), а профиль со списком доменов не может выиграть,
пока имя хоста неизвестно.

| # | Профиль | Отбор |
|---|---------|-------|
| 1 | QUIC / HTTP-3 | UDP 443, домены из списков |
| 2 | Голос Discord | UDP 19294-19344, 50000-65535, `--filter-l7=discord,stun` |
| 3 | Медиасерверы Discord | TCP 2053,2083,2087,2096,8443, `discord.media` |
| 4 | YouTube и Google | TCP 443, `list-google.txt` |
| 5 | Остальные сайты | TCP 80,443, `list-general.txt` |
| 6 | Telegram | TCP 80,443 по `ipset-telegram.txt` |

Профиль Telegram обязан идти **последним**: у MTProto нет имени хоста, поэтому
он отбирается только по подсетям и с `--dpi-desync-any-protocol`.

Профиль 4 переключается из интерфейса — блок «Стратегия YouTube и Google»
предлагает семь вариантов десинхронизации, включая «Выключено» как эталон для
сравнения. Какая техника пробивает DPI, зависит от провайдера, поэтому вариант
подбирается перебором.

Вся сборка команды живёт в одном месте — [`src/lib/zapretCommand.ts`](src/lib/zapretCommand.ts).
Там же зафиксированы правила ядра, нарушение которых роняет `winws` с кодом 1:
без `--wf-tcp`/`--wf-udp` он не стартует вообще, а `--dpi-desync-autottl`
принимает только формат `[+|-]<delta>[:<min>[-<max>]]`.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

Скрипт ставит зависимости, собирает фронтенд через Vite, пакует ресурсы и
компилирует exe через `csc.exe` из .NET Framework 4. Результат —
`release-v<версия>\Zapret2-GUI-v<версия>-portable.exe`.

`scripts\build.ps1` сохранён в UTF-8 **с BOM**: без него PowerShell 5.1 ломает
кириллицу в выводе.

### Проверка командной строки

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify_args.ps1
```

Прогоняет все семь стратегий YouTube через `winws --wf-save` — ядро разбирает
аргументы, собирает фильтр WinDivert и выходит, не загружая драйвер. Так
проверяются пути к спискам, наличие `.bin`-пейлоадов и синтаксис всех опций.
Нужны права администратора.

## Структура репозитория

| Каталог | Что внутри |
|---------|-----------|
| `MEMORY.md` | правила ядра, история багов, смысл параметров пресета |
| `src/` | React + TypeScript интерфейс |
| `src-native/` | `NativeApp.cs` — WinForms-хост, WebView2, запуск ядра, логи, IPC |
| `scripts/` | сборка и проверка |
| `bin/` | ядро zapret и фейковые пейлоады (вшиваются в exe) |
| `host-list/` | списки доменов и подсетей (вшиваются в exe) |
| `packages/webview2/` | три библиотеки WebView2, нужные компилятору |
| `zapret-raw/` | исходники ядра v72.13 — справочник по опциям winws |
| `release-v0.1.4/` | текущая собранная версия с README и SHA256SUMS.txt |
| `src-tauri/` | остаток раннего варианта хоста, в сборке не участвует |

В дереве хранится только последняя сборка. Каталоги прежних версий удалены,
но остались в истории git — при необходимости достаются оттуда:

```bash
git checkout c0e2da9 -- release-v0.0.6
```

## Распространение и обновления

Репозиторий публичный, сборки публикуются в
[Releases](https://github.com/snax1k/new-zapret2-gui/releases).

### Как обновляется приложение

Проверка выполняется при запуске (через 8 секунд, не чаще раза в шесть часов)
и по кнопке в настройках. Автопроверку можно выключить там же. Найденное
обновление окно не открывает — о нём сообщает плашка в боковом меню.

`checkForUpdates` сравнивает `APP_VERSION` с `tag_name` последнего релиза.
Если вышла новее — предлагает поставить:

1. скачивает `Zapret2-GUI-v<версия>-portable.exe` из ассетов релиза;
2. сверяет SHA-256 с `SHA256SUMS.txt` из того же релиза;
3. запускает вспомогательный `.cmd`, который ждёт выхода процесса по PID,
   подменяет exe и стартует новую версию.

Третий шаг нужен потому, что запущенный exe нельзя перезаписать самому себе.

**Установка выполняется только при наличии `SHA256SUMS.txt`.** Нет
контрольной суммы — кнопка не показывается: иначе приложение запускало бы
непроверенный файл с правами администратора. Ссылка на загрузку проверяется
на принадлежность github.com.

Ядро zapret этим механизмом не обновляется: `winws.exe` и WinDivert вшиты в
exe ресурсами и приезжают только с новой сборкой.

### Версия живёт в четырёх местах

`scripts/build.ps1`, `AppVersion` в `src-native/NativeApp.cs`, `APP_VERSION`
в `src/context/AppContext.tsx` и `version` в `package.json`. Разойдутся —
проверка обновлений начнёт врать. Сборка падает с понятным сообщением, если
значения не совпали.

В разметке версию писать нельзя: заголовок окна и стартовая запись в логе
берут её из `APP_VERSION`. Сборка отдельно проверяет, что строк вида
`v0.0.0-portable` в `src/components` и `src/views` не осталось.

### Публикация релиза

```powershell
$env:GITHUB_TOKEN = "ваш_токен"
powershell -ExecutionPolicy Bypass -File scripts\publish_release.ps1
```

Создаёт тег и релиз, заливает exe и `SHA256SUMS.txt`, описание берёт из
`release-v<версия>/README.txt`. Токен читается из переменной окружения и в
репозиторий не попадает.

## Антивирусы и ложные срабатывания

Сборки этого проекта время от времени попадают под эвристику антивирусов.
Windows Defender определял `v0.1.4` как `Trojan:Win32/Wacatac.B!ml`,
Яндекс.Браузер отказывался её скачивать. Суффикс `!ml` — вердикт машинного
обучения, а не совпадение с сигнатурой.

Приложение собирает на себе все признаки, на которые такая эвристика
реагирует:

* **не подписано** — издатель для системы неизвестен;
* **нулевая репутация** — файл новый и скачан считанные разы;
* **поведение действительно похоже на нежелательное** — распаковывает из
  ресурсов драйвер сетевой фильтрации WinDivert, ставит его и вмешивается в
  чужие TCP-соединения. Инструменты класса zapret многие движки штатно
  относят к HackTool.

Третий пункт не устраняется: это и есть назначение программы.

### Что помогает, а что нет

| | результат |
|---|---|
| Подпись кода сертификатом | решает задачу; репутация накапливается на издателя, а не на каждый файл |
| Отправка ложного срабатывания вендору | снимает конкретный вердикт за 1–3 дня, но без сертификата — на каждую сборку |
| Пересборка | **не помогает.** Вердикт возвращается, когда облачная модель оценивает новый файл: у `v0.1.4` это заняло около двух часов |
| Упаковка в архив | **не помогает.** Defender проверяет содержимое архивов — `.7z` со сборкой внутри был опознан так же |
| Переименование, сжатие упаковщиком | делает хуже: сами по себе признаки вредоноса |

Проверять надо **скачанный** файл, а не собранный локально: срабатывание
происходит по метке «загружено из интернета». Если после скачивания файл не
читается — его забрал антивирус.

### Как убедиться, что сборка не подменена

В каждом релизе рядом с exe лежит `SHA256SUMS.txt`.

```powershell
Get-FileHash .\Zapret2-GUI-v0.1.4-portable.exe -Algorithm SHA256
```

Совпало со строкой в `SHA256SUMS.txt` — файл ровно тот, что собран из
исходников. Не совпало — запускать нельзя.

Обновление внутри приложения сверяет сумму само и **не устанавливается**,
если она не сошлась или если `SHA256SUMS.txt` в релизе нет: иначе
приложение запускало бы непроверенный файл с правами администратора.
